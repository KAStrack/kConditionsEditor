## The bundle could not be a concatenation

Each source is its own UMD module. Concatenated as-is:

- all three would take the CommonJS branch under a bundler and overwrite each
  other's `module.exports`;
- `require('./k-conditions-evaluator.js')` names a file that is not next to the
  bundle.

So `build.js` wraps each source in a scope carrying its own `module` and a
`require` that resolves from an in-bundle registry by basename, and the bundle's
**own** UMD wrapper decides what to export (`{KConditions, KConditionsSql,
KConditionsEditor}` under CJS; both globals in the browser). The sources are
embedded verbatim — nothing is rewritten, so there is no second copy of the
semantics to drift.

Note the CJS export *shape* of the bundle differs from the individual files
(which keep their existing shapes). Documented.

## Load order is load-bearing in both bundles

`build.js` states it explicitly: the evaluator must come first, and
`k-conditions-skins.css` must come **after** `k-conditions-editor.css` — the
skins deliberately override the base at equal specificity and rely on being
later in the cascade. Reversing the CSS order would silently undo the 0.0.13
fix.

## Two bugs found by verifying the build

1. **`debug: true` + `collapsible: false` threw and the editor never rendered.**
   `buildSourcePanel` did `footer.insertBefore(sourceButton, this.doneButton)`,
   but `doneButton` is only *appended* to the footer when `collapsible` is true —
   so `insertBefore` got a node that was not a child. **Present since 0.0.4**,
   invisible because every test used one option or the other, never both. The
   new dist page happened to set both.
   → *Cross the option combinations, not just the defaults.*
2. The per-file minified copies still `require`d the **unminified** sibling, so
   `require('dist/k-conditions-sql.min.js')` could not resolve. The build now
   relinks `./k-conditions-*.js` → `./k-conditions-*.min.js` in the per-file
   outputs only (the bundle's shim strips to basename, so it must be left
   alone).

## tests/browser/dist-bundles.js

Treats "minified" as the semantic claim it is:

1. All 34 evaluation + 34 SQL fixtures run through the **minified** evaluator and
   SQL builder and must agree with the sources character for character.
2. CommonJS shapes of every dist file, including that the bundle wires
   `toSql` onto its own evaluator instance and that its `VERSION` matches
   `package.json`.
3. The bundle drives a real editor in Chromium with **nothing else loaded**, and
   its summary, the result of a `+AND` click, its SQL, its previews, and the
   computed styles of the brackets and the NOT marker are compared against both
   the per-file dist build and the source build. All three must be identical.
