# Notes — 0.0.21

Two requests in one message, which turned out to share a root: **the editor was
answering questions with the wrong piece of information.**

## The report

> Right now, if the type is an enum, contains, does not contain, starts with,
> ends with, matches regex and not matches regex all show a dropdown, but it
> should be an input for those operations.
>
> Also, is there a blanket way to remove the value/field picker, and only allow
> value?

---

## Part one — the operator decides, not the field

The line was:

```js
if (choices && choices.length && (kind === 'choice' || (field && field.type === 'enum'))) {
```

`field.type === 'enum'` is the mistake. Whether the value control should be a
choice list is not a property of the field — it is a property of **the operator's
operand**. `is equal to` compares against a whole value, and on an enum that
value is one of the choices. `contains` compares against a *substring*;
`matches regex` against a *pattern*. Neither is a choice, and with a dropdown
there was no way to type `contains "lor"` at all — the control physically could
not express the rule.

Fix: a new operator metadata flag, **`valueFromChoices`**, true by default and
false on exactly six operators — `contains`, `not_contains`, `starts_with`,
`ends_with`, `regex`, `not_regex`. `in_list` / `not_in_list` keep it true,
because a list of whole values *is* drawn from the choices.

### The second bug the flag exposed

The same missing distinction was corrupting `describe()`. Choice labels were
applied to every value, so a rule looking for the letters "FL" rendered as:

```
[State] contains "Florida"      ← wrong: a different rule from the one stored
```

That is worse than a cosmetic bug — an audit log or a confirmation page would
show the reader a rule the system is not running. The same flag gates the label
lookup, in both SDKs:

```
[State] is equal to "Florida"   ← eq: a whole value, so the label
[State] contains "FL"           ← contains: a substring, left alone
[State] is one of ["Florida", "Texas"]   ← whole values, so labels
```

**Where the flag lives matters.** It is not an editor option, because the editor
is not its only consumer: `describe()` runs server-side in PHP with no editor
anywhere. Putting it on the operator means the editor's control and the
description can never disagree about what kind of thing the operand is — the
same "when two things must agree, make them one thing" move as the 0.0.16 plan
functions and the 0.0.20 shared describe walker.

Seven shared fixtures pin it. Removing the flag fails exactly those seven, which
is the check worth running whenever a fixture is added: *a fixture that passes
before the fix is pinning nothing.*

## Part two — the Value / Field picker, now off by default

There was no blanket switch. Per field you could set `comparableWith: false` or
`values: ['literal']`, but the **default** for a field that said nothing was
"comparable with every other field of the same type" — so a form with four text
fields silently offered field-to-field comparison on all four and paid a
selector on every row for it.

Ben chose to flip the default rather than only add an opt-out. New option
**`allowFieldValues`, default `false`.**

Three details that make the flip safe:

- **A field naming `comparableWith` opts itself in.** Without this the per-field
  setting would be unreachable without also setting the global, which is a
  confusing pair of switches. It also means the README quick-start example
  (`email` comparable with `billing_email`) keeps working untouched.
- **`comparableWith: false` still wins** when the global is on.
- **An existing field reference always keeps its selector.** A loaded document
  may hold `{source: 'field', field: 'other'}` written before the option was
  turned off. Hiding the source selector then would leave no way back to a
  literal — the rule would be stuck. And the referenced field is listed in the
  dropdown even when the current `comparableWith` rules would not offer it,
  because an empty selector beside a live reference reads as comparing against
  nothing.

The principle: **a setting governs what can be created; it must never become a
trap around what already exists.**

## The test that had been red for weeks

`hover-focus-reveal.js` (then `verify8.js`) was failing before this change and
had quietly dropped out of the release regression — the regression was an
explicit list of scripts, and it omitted that one.

The cause was in the test, not the product. The script focuses an add button to
check keyboard reachability, and **the add preview fires on focus as well as
hover** — deliberately, so a keyboard user gets the preview too. That leaves a
`.kce-ghost` row in the DOM. The ghost is inserted into the flow layout's line
list, so the next step's `lines[1]` was a ghost rather than a condition, and
Playwright's actionability check kept reporting the tree container as
intercepting because the DOM shifted under it.

Fix: park the pointer, blur, and wait for `.kce-ghost` to leave before
measuring. Also replaced two `locator.hover()` calls with hit-tested
`mouse.move()`, since the point of the test is what a hovering user gets rather
than what Playwright considers actionable.

Two lessons:

- **Anything that inserts DOM on hover or focus invalidates a measurement taken
  after it.** This is the 0.0.12 "re-measure after hovering" lesson with a new
  cause — that one was the add buttons widening a row, this one is a ghost row
  being added to it.
- **A permanently red script is worse than no script**, because the suite stops
  being read. The release regression should be "run everything", not a list.
  0.0.22 turned that into `npm run test:browser`, which runs the directory.

`docs-describe-styles.js` also hardcoded `0.0.20` and went red on the version
bump; it now reads the version from `package.json`.

## Shipped in 0.0.21

- `valueFromChoices` operator metadata, JS and PHP.
- Editor renders a text input for fragment/pattern operators whatever the field
  type.
- `describe()` / `describeHtml()` no longer relabel fragments, both languages.
- `allowFieldValues` option, default `false` — **a behaviour change**, called out
  as such in the CHANGELOG, README and docs.
- 7 new shared describe fixtures (JS 102 → 109, PHP 96 → 103).
- `value-control.js`: control type per operator, the field-picker default,
  per-field opt-in and opt-out, and the existing-reference escape hatch.
- `hover-focus-reveal.js` and `docs-describe-styles.js` repaired.
