# Notes — 0.1.3

Ben: field and value lists can be long; many projects using the editor also
use kSelect. Detect it and use it; an option to force it off, or on — and if
forced on with no kSelect on the page, load it from a CDN.

## One mechanism

0.1.2's `decorateSelect` / `releaseSelect` / `focusSelect` already did
everything a widget needs: offer each select after every render, release
before a redraw, keep focus through it, measure the widget when it lands. The
built-in kSelect is the editor acting as that host (`decorateWithKselect`,
`kselectDecorate`, release through `getInstance().destroy()`), so it cannot
behave differently from a host's widget. `adoptDecorated()` is the shared tail
of both paths. A host's own `decorateSelect` wins outright: the host knows its
page.

## Decisions (asked)

- **Which selects:** the long lists (field, compared-with field, value
  choices, list of choices). The operator keeps its `{value}` slot; Value /
  Field has two entries. A role, not a length threshold: a length rule would
  make the same row mix widgets and native selects as data changes.
- **Look:** the skin's. A boxed control in a prose row is the regression the
  prose skin argues against. Closed, the kSelect is styled as the label it
  replaces, scoped `.kce:is(…) .kce-sel-ks .ks-…` so a host's `.ks-control`
  form-control rules (HDC's) cannot box it; it shrinks like the label
  (`fitRows()` reads `.ks-single-value` as its label). Open, its search box
  lies over the word (absolute), so nothing moves.

## Detection, loading, arriving late

- `'auto'`: `window.Kselect` with `init` and `getInstance`. Checked on every
  decoration pass. A host that `import()`s kSelect after attaching leaves no
  `<script>` to watch, so editors that found none wait on a page-wide watch
  (100 ms … 8 s, and `load`); a hit upgrades the waiting selects in place. A
  list of choices cannot wait bare (a `<select multiple>` is a listbox), so it
  gets chips and the rule is redrawn on arrival — the one redraw.
- `true`: one load per page, `<script integrity crossorigin>` and the
  stylesheet if kSelect's tokens are not on `:root`. The SRI hashes are of the
  v1.11.0 tag's files; `tests/js/kselect-pin.test.js` holds them to the
  vendored copy, which the browser checks serve in place of the CDN.
- A host-named `kselectSrc` gets no pinned hash (it would be the hash of a
  different file); only the integrity it names.

## The layer, and the dialog

A list opened from the tree would be clipped by it (`overflow-x`); kSelect's
default `<body>` portal loses the editor's tokens and dark mode. So each
editor has a layer: a `.kce` carrying its theme and skin, passed as
`dropdownParent` (kSelect ≥ 1.10). It inherits every token block and a host's
`.kce` overrides.

The first check put an editor in a modal `<dialog>` and found the opened list
in the dialog but not painted: a modal dialog is `overflow: auto` and clips
fixed descendants that overflow it, and is drawn above `<body>`. The layer is
now a `popover="manual"`, shown, in the dialog when there is one (outside it,
a modal dialog makes everything inert) — in the browser's top layer, above the
dialog and clear of any clipping or transformed ancestor. It is re-shown each
time a list opens (`kselect:open`), because a dialog opened after the layer
was shown sits above it; the check opens the dialog both before and after
attaching, and fails without the re-show.

## What the checks found

- A long value kSelect overflowed its slot by 13px at 545px: the 0.1.2 rule
  holding host widgets at `flex: 0 0 auto` kept the wrapper from shrinking
  for the chevron. The editor's own kSelect overrides it.
- Boxed at 545px, a date range scrolled 3px: kSelect's 1.5px border and its
  padding made the field box wider than boxed's own. Matched.
- The closed word was 21px tall; its hit area now reaches 24px unseen.
- axe, with each kind of list open: kSelect 1.11.0's listbox contains a live
  region and a group-toggle button (`aria-required-children`). That is
  kSelect's markup, to fix there; the check exempts that rule on `.ks-dropdown`
  alone and prints a NOTE, so it is not forgotten.

Checked against kSelect 1.9.0 (HDC's copy) as well: works, lists in `<body>`.
